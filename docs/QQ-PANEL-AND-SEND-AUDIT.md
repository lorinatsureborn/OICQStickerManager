# QQ 表情联动与上屏修复记录

日期：2026-10-07。实机环境：Windows 11、QQ 9.9.19.35469、300% DPI。

## 原因与修复

| 实测问题 | 原因 | 当前处理 |
| --- | --- | --- |
| 原生面板关闭后快捷面板滞留 | 关闭依赖 QQ 的 UIA 事件；剪枝树、延迟事件和存活时间回退不能代表实际窗口生命周期 | 主进程独立监听鼠标和窗口状态。QQ 外、消息区、输入区等区域的按下立即收起；隐藏、最小化、销毁、前台切换另由 50ms 原生状态检查兜底，完全不调用 UIA |
| 关闭后又被旧事件弹出 | 辅助进程尚在处理旧的打开/可见帧 | 主进程与辅助进程分别记录关闭操作代次；同代旧帧不能恢复打开状态，新按钮操作才解除屏障 |
| 打开一段时间后误收起 | QQ 会遗漏结构事件，或复用旧面板节点而不再次发事件 | 已验证的按钮打开不再仅凭 TTL 收起；原生生命周期监听负责主动关闭。已相关的节点可在新操作中重新确认，但须重新匹配宿主、进程、可见性与面板尺寸 |
| 已关闭节点又被判为面板 | QQ 复用该节点并改变它的尺寸；此前只要求矩形非空 | 检查原生面板尺寸，关闭时清除打开锚与待确认状态；保留的节点身份不能越过关闭代次屏障 |
| 冷启动首次点击不联动 | 原像素模板含鼠标图像，干净模板与实际图标不匹配 | 修正采集，等待鼠标离开，截取后再次检查；允许修复旧版模板。本机已用生产 GDI 采集重新校准模板并重启验证首次点击 |
| 点击后表情未进入输入框 | 本程序的 SendInput 点击被鼠标监听当作其他注入输入丢弃；剪枝 UIA 元素没有完整类名/矩形时，焦点证据因此无法建立 | 给本程序点击加专用标记，单独记录编辑点击证据；它不会成为用户的按钮操作，也不会触发关闭守卫 |
| 重试仍误判焦点失败 | 第一次点击已成功，UIA 回声迟到；第二次点击同一编辑框不再产生新焦点事件 | 回声必须晚于本轮焦点恢复开始，并仍是当前编辑焦点；不再强求晚于每次重试点击 |
| 恢复点击被快捷面板挡住 | 淡出期间置顶窗口仍实际存在，遮挡输入区 | 发送开始、QQ 原生面板消失时立即真正隐藏，并取消尚未结束的动画/隐藏定时器 |
| 等待剪贴板时焦点变化导致落空 | 最后编辑焦点检查与 Ctrl+V 之间仍可发生剪贴板重试、用户点击 | 每次剪贴板重试及粘贴之前重新核对目标、编辑焦点、按钮操作代次与用户鼠标操作；不强行抢回用户已切走的前台窗口 |

## 上屏路线

保留“原始图片文件 → 文件列表剪贴板 → QQ 编辑框 Ctrl+V”。本机实际 GIF 已成功进入 QQ 草稿；这条路径保留原文件内容和动态图片，且使用 QQ 自身的粘贴入口。

问题主要出在焦点与面板关闭编排，而非改换图片传输格式。旧版 QQ 先关闭已知打开的原生面板，等待焦点编排平息，再点击聊天编辑区以建立插入符。UIA 用于确认和定位；不使用 UIA SetFocus 作为编辑点击的替代。删除粘贴后延迟 800ms 再 toggle 表情按钮的补关，以免重新打开原生面板。

本轮未引入 QQ 协议发送、插件注入或 Enter 发消息。发送结果中的 `Sent` 表示系统接受了输入序列，不能单独证明 QQ 文档内容；真实草稿上屏另经窗口截图确认。

- 点击 QQ 消息区、输入区：两个面板同时收起；原生监听日志至 UI 隐藏约数毫秒。
- 再点表情按钮、快速双击：最终两个面板均关闭，没有延迟重开。
- 最小化 QQ、关闭 QQ 界面：快捷面板随即收起；最小化后恢复 QQ 没有自动误弹。
- 切换到外部应用：无鼠标关闭信号时，原生前台状态检查仍收起快捷面板。该 QQ 版本通过程序激活切窗有时保留原生面板，因此这项与真实鼠标点击外部区域应分别看待。
- Escape：本机该面板不会因 Escape 关闭；当前实现查询实际可见状态，避免按 Escape 单独误收起快捷面板。
- 真实发送：通过生产 `WindowService.CoexistPasteAsync`，GIF 成功出现在 QQ 输入框；测试仅插入草稿，没有发送消息。
