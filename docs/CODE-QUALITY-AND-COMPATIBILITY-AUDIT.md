# Asuka 代码质量与 QQ 兼容性审查

更新：2026-10-06。包含首轮通查、可靠性修复、UIA 进程隔离、真实 9.9.21 联动测试及精确 9.9.19 的模块分析、面板生命周期、GIF 粘贴、300% DPI 布局、立即取密钥与深度同步验证。目标为旧 NTQQ 9.9.19.35469、9.9.21.38711 和新版本；附近版本不能替代精确历史版本验收。

## 整体评价

**技术栈合适，核心功能已成型。精确旧版的面板联动、GIF 粘贴、立即取密钥和仅标记对账已取得实机证据，但复杂环境与全部功能组合尚未验收。**

| 维度 | 评价 |
| --- | --- |
| 技术栈 | C# / WPF / Win32 适合 Windows 托盘、热键、剪贴板和桌面联动。无需为兼容 QQ 更换 UI 框架。 |
| 架构 | 具备 Models / ViewModels / Services / Views 分层；已拆出发送事务、保存队列、进程能力、原生输入、硬件调试器和 UIA 进程边界。MainViewModel、MainWindow、QqPanelWatcher 仍然过大，事件和窗口状态仍较耦合。 |
| 核心功能 | 导入、标签、排序、虚拟化、快捷面板、三档同步、立即取密钥和下次自动取密钥均保留。发送结果、收编失败、恢复队列及在线 WAL 有了独立回归；本机 9.9.21 已完成两次 GIF 粘贴及发送记录核对，9.9.19 已核对收藏、GIF 标签下的两次草稿及随后手动发送记录。精确 9.9.19 已捕获真实密钥，完成数据库认证、仅标记对账和重启复用；自动捕获、三档策略的全部实机组合仍未验收。 |
| 环境兼容 | 已改善新旧 QQ 共存、晚启动、重启、自定义路径、配置迁移、剪贴板争用、权限拒绝、负坐标与 DPI 计算。尚缺多个 Windows / QQ / 输入法 / 显示器组合的端到端证据。 |

推荐继续围绕 QQ 适配与状态机收敛架构，不做整项目重写。UIA 可回收隔离已落地，后续重点是按聊天窗口的面板状态、精确历史版本及复杂环境矩阵。

## 剩余风险

### P1：复杂环境与功能组合的端到端证据仍不足

本机 QQ 关于页面确认 9.9.21-38711（64 bit），Windows 11 10.0.26300。远程桌面保持连接后截图恢复；被遮挡时需要先激活 QQ 再核对，不能凭遮挡截图操作。此前截图错误与会话状态有关的推断尚未通过断开/重连对照证明。

真实测试只使用个人会话「バカ夏 / 1035237804」，独立数据目录中只有一张非私人卡通 GIF。复现了面板宿主解析失败、焦点回摆造成安全取消、GIF 标签关闭点偏移及面板遮挡。修复后分别核对了预热编辑区和启动后只有 GIF 标签信号的两次草稿与发送记录；两张测试 GIF 均出现在该单聊中，没有操作群聊。

冷启动路径的耗时仍受 QQ 焦点事件延迟影响；本次成功不能替代持续重复、物理鼠标及其他输入法验收。上述 9.9.21 测试阶段没有附加真实 QQ 调试器或执行第三方取密钥脚本；后续 9.9.19 的真实助手先被火绒阻止，用户放行后已捕获密钥并完成仅标记对账，详见下节。真实自动捕获、同步删除、挪入图库和频繁在线 WAL 写入尚未完成同等验收；相关组件夹具不能代替实机组合。最新版真机共存、提权及混合 DPI 也仍未完成。

### P2：仍有平台边界与状态证据风险

- 全局输入与剪贴板检查存在检查后改变的竞态；系统接受 Ctrl+V 不等于 QQ 已上传或对方收到，结果文案明确为“粘贴到目标窗口”。[微软 SendInput 的权限与返回值约定](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)也不提供聊天业务确认。
- QQ 几何启发点、标签间距及合成面板尺寸仍包含经验值；现已分别观察 9.9.21 与精确 9.9.19，不能推广到全部历史版本。结构节点关联也依赖宿主、代次和几何，不是腾讯公开语义接口。极窄工作区与其他面板布局还需检查。
- 剪贴板 COM 阻塞时旧线程可以存活；本轮防止迟到结果，但完全限制阻塞线程数量仍需隔离提取。
- 加密快照稳定性采用保守重复读取，不是持有 SQLite 原生读锁的事务快照；需在真实 QQ 高频写入、checkpoint 与账号切换下继续测试。支持之外的格式保留镜像并提示。
- 密钥保护不能自动消除旧版本已生成的原始输出、日志或损坏备份；本轮没有擅自清除这些历史用户文件。DPAPI 不保护已被相同用户权限恶意程序控制的会话。
- UIA 隔离覆盖异常回收、正常退出和真实事件联动，但仍需事件风暴、反复重启与长时间资源测试。
- 仍需 Windows 10、远程桌面断开/重连、提权 QQ、多聊天窗口、多显示器混合 DPI、非中文区域设置和第三方 IME 验收。模糊 API 成功也不能证明所有驱动视觉都正确。

## 发布与系统范围

当前 net10.0-windows，发布为 win-x64、SelfContained=false，用户需要相应 Windows Desktop Runtime。单文件不是自带运行时；自动调试取密钥只支持原生 AMD64 目标，不能据此宣布 x86 / ARM64 QQ 可用。

应公布验证过的具体 OS build、QQ 版本、架构与功能范围。[.NET 10 官方系统支持表](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md)中的厂商支持与本项目实测覆盖是不同概念。
