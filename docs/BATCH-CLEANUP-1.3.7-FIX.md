# Asuka 1.3.7：批量清理后无法退出与 QQ 预览回退

2026-10-23 根据保留的 1.3.6 运行现场修复，已替换 `D:\Asuka\Asuka.exe`。

## 现场与原因

- 原主进程 PID 53548 仍响应，批量工具栏整体禁用，界面没有可见的确认弹窗。
- 保存堆转储后确认：`BatchDelete_Click` 的状态机停在状态 3，等待当前结果弹窗的 `Task<bool>`；`AlertOverlay.Visibility` 已为 `Collapsed (2)`。
- 结果框内容实际为清理 0 张、保留 1 张。本次没有删除该图片，418 个 QQ Ori 缓存文件与此前的部署校验清单一致。
- 确认框和结果框共用浮层。关闭确认框的 160ms 淡出动画回调没有检查浮层是否已重新打开，可能在结果框显示后将其隐藏。删除处理又把工具栏解锁放在结果框确认之后，导致无法点击「完成」。
- 之前的 WPF 用例在动画结束前就确认结果框，只检查标题，没有等到旧动画回调，漏掉了这条路径。新增等待 350ms 后检查可见性的断言，在旧实现上复现了失败。
- 神秘图片是另一处预览问题：原 JPG 83666 字节，WIC 解码报 `0x88982F72`；对应的 QQ PNG 缩略图 25233 字节，可正常解码。

## 修复

- 每个浮层维护独立的显示代数。重新打开浮层前使旧关闭回调失效，旧动画不能隐藏新弹窗。
- 文件操作结束立即解锁工具栏，再显示结果提示；关闭结果框不再决定工具栏的生命周期。异常也给出明确提示。
- QQ 原图无法解码或缺失时，回退到 QQ 自带缩略图并缓存解码结果。发送、AI 识别和删除仍使用原文件路径，不改写原图。
