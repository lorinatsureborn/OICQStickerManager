# Asuka 1.3.8：QQ 收藏、缓存残留和待核验状态

2026-10-23 根据 1.3.7 运行现场修复，已替换本地运行版。

## 现场与原因

- 当前账号的 QQ 索引认证与 SQLite 完整性检查通过，权威收藏索引有 409 条。
- 现场堆中当前镜像有 418 张，9 张 `IsOrphaned=true`；对账摘要为“发现 9 个缓存残留”。
- 图片名称和页脚却把所有条目统称为 QQ 收藏，缓存残留只用一个淡色小图标标记，未准确表达后端判断结果。
- 目录全量重扫、同名文件重写还会创建新模型，原来的已核验状态没有继承，直到下次对账才恢复。新增回归在旧实现中复现了此问题。
- 原先 `IsOrphaned=false` 同时代表“确认仍在收藏”和“从未核验”，导致新加载、读取失败的图片也被当成收藏展示。

## 修复

- 增加仅在内存中的“是否已核验”状态，分别展示 QQ 收藏、缓存残留、待核验。
- 已移除条目的名称为“QQ缓存残留”，卡片左上角显示清楚的文字角标；未核验显示“待核验”。重新收藏后同步移除残留角标。
- 页脚分别统计收藏、缓存残留、待核验，对账完成后主动刷新统计。
- 同路径、同 MD5 的文件在全量重扫及同名重写时继承已核验状态，保留上次有效判断；后续权威索引仍可纠正重新收藏的状态。
- 删除前继续读取权威索引核验，不以保留下来的旧角标作为删除依据。
