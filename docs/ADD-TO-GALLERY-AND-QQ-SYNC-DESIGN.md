# 设计：图片入库深化 —— 聊天图片入库入口 + QQ 表情标签页与双向同步

> 先导设计文档，2026-09-30。本文档只做设计与取证，未改任何代码。
> 结论先行：**两条新特性都不需要注入 QQ**。特性一走「剪贴板捕获 + QQ 原生收藏联动」，特性二走「缓存目录镜像 + 文件监视」，全部复用本项目已验证的技术栈（只读文件系统、UIA 感知、剪贴板通道）。唯一有门槛的深度对账能力（读取 emoji.db 权威索引）作为可选增强，方案与降级路径都已明确。

---

## 1. 现状盘点：现有"加入表情"的全部途径与规则

### 1.1 入口（只有一条）

| 入口 | 位置 | 链路 |
|---|---|---|
| **拖放导入**（唯一入口） | 主窗口表情网格 `ListBox_Drop`（MainWindow.xaml:140） | 拖入文件/文件夹 → `MainViewModel.AddStickersFromPathAsync` → 完成后弹**批量标签编辑器**（tag chips，可输入新标签或点标签池）→ `SaveDatabaseAsync` |

没有"添加文件"按钮、没有剪贴板监听、没有右键导入。拖放是唯一通路。

### 1.2 处理规则（AddStickersFromPathAsync，MainViewModel.cs:210）

1. 文件夹则递归枚举，扩展名白名单 `.jpg .jpeg .png .gif .webp .bmp`；
2. **复制**（非移动）到 `Documents\OICQStickerManager\Library\`，重命名为 `Guid.ext`；
3. 新建 `StickerModel`（空标签）加入集合，批量保存 stickers.json；
4. 单文件失败静默忽略；**无任何去重**（Guid 命名，同一张图拖两次 = 图库两条）。

### 1.3 加载与真相源规则（LoadStickersAsync，MainViewModel.cs:157）

- **物理文件是身份**：启动时枚举 Library 目录，sticks.json 仅按 `FullPath` 合并标签与 LastUsedTime；
- 物理存在但 JSON 无记录 → 以无标签新表情载入；启动后自动反向回写 JSON 修复差异；
- 删除：先移集合 → 存 JSON → 物理删除（3 次重试防占用）；
- `IsGif` 按**扩展名**判定（决定 GIF 角标与悬浮动画）。

### 1.4 与新特性相关的既有短板

- **无内容去重**：Guid 文件名不可反查内容；
- **按扩展名判型**：QQ 缓存里 1/3 文件后缀是错的（见 §2.3），直接入库会坏动图；
- **webp 是暗坑**：白名单收 webp，但 WPF `BitmapImage` 根本解不出 webp（现有图库如混入 webp 即坏图）；
- 无"半写文件"防御（将来监视 QQ 缓存目录必须有）。

## 2. 取证结果（2026-09-30 本机实测 + 外部检索）

本机 QQ 为 NT 架构（QQ.exe 运行中），账号数据在 `Documents\Tencent Files\<uin>\nt_qq\`（`nt_data` = 媒体缓存，`nt_db` = 加密索引库）。

### 2.0 范围锁定（用户 2026-09-30 拍板）

**本设计只处理表情面板里的「爱心分页」**——即用户点击 QQ 表情按钮弹出面板后、心形图标那一页（我的收藏表情），也就是在聊天里右键图片点「添加到表情」后表情会进入的那个分页。它对应的本地目录就是 `nt_data\Emoji\personal_emoji\`。

明确排除（以下分页/目录一概不考虑，设计与其零耦合）：

| 面板里的东西 | 本地位置 | 状态 |
|---|---|---|
| **爱心分页（我的收藏表情）** | `Emoji\personal_emoji\` | ★ 唯一目标 |
| 默认小黄脸/系统表情分页 | `Emoji\BaseEmojiSyastems\` | 排除 |
| 商城/超级表情分页 | `Emoji\marketface\`、`Emoji\emoji-recv\` | 排除 |
| 最近使用（面板顶部一条） | 无独立目录（走历史记录） | 排除 |
| 消息收藏（左侧「收藏」星标夹） | `collection.db` 等 | 排除（注意与「添加到表情」是两个功能） |

边界注记：若爱心分页里还包含"从商城收藏的整套表情"，那部分落在 `marketface`，同样按用户定义排除——范围就是「添加到表情」产生的个体表情，不多不少。

### 2.1 收藏表情的真实位置 —— 用户表情面板"我的收藏"

```
Documents\Tencent Files\<uin>\nt_qq\
├── nt_data\Emoji\
│   ├── personal_emoji\          ★ 收藏表情（本设计的目标目录）
│   │   ├── Ori\                 原图 441 个（166MB）
│   │   └── Thumb\               静态缩略图 png 405 个（= jpg 数；gif 无缩略图）
│   ├── emoji-recv\              聊天图片缓存 8.5GB（按月）——不碰
│   ├── marketface\              商城表情 45MB——不碰
│   └── BaseEmojiSyastems\       系统小黄脸 225MB——不碰
└── nt_db\
    └── emoji.db                 收藏表情的权威索引（795KB，SQLCipher 加密）
```

- 目录**活跃**：最新文件 2026-09-29（昨天），用户收藏即落盘；
- 第二个账号没有 `personal_emoji` 目录 → 目录按需创建，**代码必须容忍缺失**。

### 2.2 文件名 = 内容大写 MD5（实测 8/8 全中）

`Ori\01206820C95E256637EC0E9AC32ADA2A.jpg` 的文件内容 MD5 = `01206820C95E256637EC0E9AC32ADA2A`。

→ **免费获得内容级去重键**：QQ 导入查重、图库「已导入」标记都不需要读文件内容，比对文件名即可。

### 2.3 后缀不可信，必须魔数嗅探（实测）

Ori 内 441 个文件的真实格式：**144 GIF + 257 JPEG + 40 PNG**，但按扩展名统计是 36 gif + 405 jpg —— **148 个（1/3）后缀错误**，GIF 动图普遍被存成 `.jpg`。

入库规则定为：读文件头判真格式——`FF D8 FF`=JPEG、`GIF87a/89a`=GIF、`89 50 4E 47`=PNG、`RIFF..WEBP`=WebP、`BM`=BMP，**落盘扩展名以魔数为准**。与 [dogxii/BackupQQEmoji](https://github.com/dogxii/BackupQQEmoji) 的结论一致。

### 2.4 删除行为：缓存 ≠ 权威（决定同步架构的关键事实）

- BackupQQEmoji 文档明示：**"Ori 文件夹可能跟现在收藏表情有出入"**，QQ 不保证在取消收藏时删除缓存文件；对面板懒加载（不滚到底不下载），[QQFavoriteExtract](https://github.com/VanillaNahida/QQFavoriteExtract) 同样要求"翻到底加载完再提取"；
- 即：**目录镜像对"新增"实时可靠，对"删除"可能只增不减**；
- 权威列表在 `emoji.db`，但它加密（见 §2.5）。删除行为在本机当前 QQ 版本上的真实表现 → 用**探针 P1**（§6）实测后定方案，两条路线都已设计好（§4.4）。

### 2.5 emoji.db 的加密形态与解密可行性

本机实测：文件头 16 字节是明文 `SQLite header 3`（页大小 1024），**偏移 32 处出现 `QQ_NT DB` 魔数**——即 SQLCipher「32 字节明文头 + 加密页」形态。外部证据：

- [QQBackup/qq-win-db-key](https://github.com/QQBackup/qq-win-db-key)（1092★，2026-07 仍在更新，QQ 9.9.32-51246 已验证"确认可用"）：密钥 = **16 字符 passphrase**（形如 `#8xxxxxxxxxxx@uJ`），在 `wrapper.node` 的 `nt_sqlite3_key_v2` 调用处取得；官方 PowerShell 脚本走**只读进程内存分析**（无注入）；注意 hook 到 20 字节 key 是 login.db 的全设备硬编码密钥，不是目标；
- [QQDecrypt 文档](https://qqbackup.github.io/QQDecrypt/)：SQLCipher 参数（明文头 32、页 1024 与本机实测一致，其余参数实现时对拍）；
- 纯 C# 实现路径：PBKDF2 + AES + HMAC 全在 System.Security 内，emoji.db 仅 ~800KB，解密到内存/临时副本即可用 Microsoft.Data.Sqlite 读，**零原生依赖**。

### 2.6 右键菜单注入路线已死（决定特性一不走注入）

- [LiteLoaderQQNT](https://github.com/LiteLoaderQQNT/LiteLoaderQQNT) **2026-05-17 已归档只读**；README 明确警告 QQ 安全中心可能按"非法外挂工具"下线设备/封号；新版需 dbghelp.dll 或 QQNTFileVerifyPatch 绕过文件校验——官方对抗持续升级；
- DLL 注入摸不到 Chromium DOM、UIA 造不出菜单项（项目记忆中 2026-09-29 已论证）；
- **结论：在 QQ 原生菜单里塞我们自己的菜单项 = 不可行且不值得**。特性一改走零注入分层方案（§3）。

## 3. 特性一：在 QQ 里把当前图片送入图库

目标场景：用户在 QQ 聊天窗口看到一张图/表情 → 一次顺手操作 → 入飞鸟图库。分三层，前两层即覆盖全部日常场景。

### 3.1 L1 剪贴板图片捕获（通用入库入口，v1 核心）

**操作流**：QQ 里右键图片 → 点 QQ 自带的「复制图片」（或 Ctrl+C）→ 飞鸟弹出轻提示（非激活 toast / 托盘气泡，不抢焦点）「图片已捕获 · 入库？」→ 点击（或再按热键）→ 落临时文件 → 走既有 `AddStickersFromPathAsync` + 标签编辑器。

- 实现：`AddClipboardFormatListener` 挂主窗口 hwnd（WM_CLIPBOARDUPDATE），`GetClipboardOwner` 过滤自家发送通道产生的剪贴板写入（发送时置 `_suppressCapture` 标志即可，与剪贴板恢复机制共用窗口）；
- 捕获对象：`CF_DIB`/`CF_BITMAP`/`PNG` 格式/`FileDropList` 中的图片文件；从 DIB 落盘时按魔数定扩展名；
- **与发送通道共存**：本项目发送=写剪贴板 FileDropList→粘贴→1s 后恢复。捕获监听必须在自家写入期间静默（标志位），恢复写入同样静默；QQ 面板共存模式的连发场景已由该恢复机制覆盖；
- 设置项 `CaptureClipboardImages`（默认开）：提示形式 = 托盘气泡 + 主窗口状态栏；点击气泡才入库，不打断当前聊天；
- **通用性红利**：浏览器、微信、任何应用里复制图都能入库——入口不止服务 QQ。

### 3.2 L2 QQ 原生「添加到表情」联动（特性一的"QQ 菜单入口"，复用特性二基建）

**操作流**：QQ 里右键图片 → 点 QQ 自带的「添加到表情」→ 表情进入爱心分页，文件落进 `personal_emoji/Ori` → 我们 §4 的 watcher 捕获 → 按设置处理：

- `QqFavoriteImportMode` = `Off / Notify / Auto`（默认 Notify）：
  - **Notify**：状态栏/toast 提示「QQ 新收藏 1 张 → 入库？」，一键导入（MD5 去重 + 魔数修正 + 自动加「QQ」标签 → 弹标签编辑器补标签）；
  - **Auto**：直接复制进 Library（同样去重、打「QQ」标签），不打扰；
- **这就是"在 QQ 原本菜单里有一个入库入口"的最终形态**：入口是 QQ 自己的「收藏表情」，管道是我们的——用户在 QQ 里零学习成本，我们零注入零风险。用户继续用 QQ 面板发这张图也完全不受影响（收藏表情仍在 QQ 里）。

### 3.3 L3「菜单旁浮标」——评估后不做（留档）

设想：检测 QQ 右键菜单弹出（UIA，复用共存触发器基建）→ 菜单旁贴非激活浮标「入库」→ 点击后 UIA Invoke QQ 菜单的「复制图片」→ 读剪贴板。**链路断裂点**：Chromium 菜单控制器在菜单打开期间全局捕获鼠标，点击浮标（即使 MA_NOACTIVATE）会先关掉 QQ 菜单，Invoke 随之落空；自动补"重开菜单再 Invoke"则闪烁且更脆弱。收益相对 L1（同样两步：右键→复制→点气泡）无实质提升。**不做**。

被否方案汇总：LiteLoaderQQNT 插件（项目已死 + 封号）、DLL 注入（摸不到 DOM）、浮标+菜单项 Invoke（§3.3）。

## 4. 特性二：QQ 标签页 + 与 QQ 表情面板的双向同步

目标：图库出现特殊「QQ」选项卡 = 用户 QQ 收藏表情的**活镜像**；QQ 面板里增/删表情，这里跟着变；支持一键导入图库、也可直接发送。

### 4.1 新服务 `QqEmojiService`（纯只读文件系统）

```
职责：
├─ 账号与绑定：见 §4.5（显式绑定模型，一对多；每个绑定一个 watcher + 一份镜像）
├─ 全量扫描：启动/手动刷新时枚举 Ori + Thumb → 内存镜像表
│   QqStickerModel { Md5(文件名), OriPath, ThumbPath?, RealFormat(魔数), FileMtime }
├─ 增量监视：FileSystemWatcher 挂 Ori（+Thumb 可选）
│   防半写：Created/Changed → 300ms debounce + 独占打开探测成功才入镜像
├─ 导入执行：复制 Ori→Library（魔数定扩展名、MD5 去重、打「QQ」标签），
│   复用 AddStickersFromPathAsync（内部扩展，见 §5.1）
└─ 降级：QQ 未装/目录缺失 → 空状态引导；watcher 异常 → 状态栏提示 + 手动刷新按钮
    （失败一律良性，与共存触发器同哲学）
```

- Thumb 优先做静态缩略图源（省解码），GIF 用 Ori；真 webp 无 WPF 解码器 → 跳过并计数提示；
- QQ 对缓存文件按需读取、不持锁，但导入/发送前仍 `File.Exists` 防护（QQ 可能清理）。

### 4.2 「QQ（账号）」选项卡（每绑定一个，虚拟标签页）

- **一个绑定 = 一个选项卡**，显示名 `QQ（别名）`，别名默认 = uin 尾号（如 uin `1234567890` 显示为「QQ（7890）」）。标签身份与显示名分离：内部键形如 `qq:<uin>`（TabTags 是字符串集合，过滤器按前缀分发到对应镜像；改名只动显示名不动身份）；
- **选项卡批量改名**：右键选项卡 →「重命名」→ 改的是绑定的显示别名，对该账号下全部表情一次性生效（所以是批量）；
- `SelectedTab` 特判分支（同「最近」的既有模式）：命中某绑定时列表 ItemsSource 切换为该账号镜像，复用现有格子模板（虚拟化、GIF 角标、入场动画全继承）；
- 格子行为：
  - **单击/双击 = 直接发送**（Ori 路径走既有发送通道，零拷贝——这一步"完美包裹"QQ 原生表情的发送功能，连导入都不用）；
  - 右键菜单：导入图库 / 在文件夹中显示；
  - 角标：已导入（Md5 命中图库）/ 未导入；GIF 角标沿用；
- 标题行附加按钮：「全部导入」（去重后批量进标签编辑器）；
- **QQ 页不进 stickers.json**——它是视图不是库数据，零迁移成本、随时可删可解绑。

### 4.3 同步语义

| QQ 面板动作 | 磁盘表现 | 我们的响应 |
|---|---|---|
| 添加到表情（爱心分页） | Ori 新增文件（下载完成时） | watcher Created → 镜像新增（准实时）；联动 L2 设置 |
| 再次收藏同一张 | 同 MD5，文件已存在 | 镜像无变化（天然幂等） |
| 取消收藏 | **待探针 P1**（可能删文件、可能留孤儿） | 见 §4.4 |
| 长期不用 | 可能被缓存策略清理 | 发送/导入前 `File.Exists` 防护 |

### 4.4 删除同步：探针 P1 定路线（两案都通向完整体验）

- **P1-a（若 QQ 会删文件）**：watcher Deleted → 镜像同步移除。纯文件系统即完美双向同步，Phase B 永不需要。工作量最小，**优先押注**（当前版本 QQ 行为可能已比 2025 年社区记载更干净）。
- **P1-b（若 QQ 留孤儿，社区记载倾向于此）**：Phase B「深度对账」可选增强：
  1. C# 移植 qq-win-db-key 的密钥提取：只读 `ReadProcessMemory` 扫描 QQ 进程定位 16 字符 passphrase + 页 1 HMAC 校验确认（无注入、无写、失败即降级）；
  2. 只读复制 `emoji.db`(+wal) → 纯 C# SQLCipher 页解密（明文头 32 / 页 1024 实测已定，其余参数对拍）→ 读出权威收藏 MD5 列表；
  3. 对账：目录有而索引无 → 镜像中灰显「QQ 已取消收藏」（**不自动删本地**，用户手动清理）；索引有而目录无 → 占位「未缓存」（QQ 懒加载所致）；
  4. 设置项 `QqDeepSync`（默认关）+ 触发时机：手动刷新 / QQ 面板关闭事件（复用共存触发器信号）；
  5. 密钥提取失败（QQ 更新改内存布局）→ 良性降级回目录镜像模式，状态栏说明。

### 4.7 P1/P3 探针结果与 Phase B 实测参数（2026-09-30，全部真机验证通过）

**P1 判定 = P1-b**：QQ 取消收藏**不删除缓存文件**（探针实录：收藏→CREATED，取消→60 秒无 DELETED，Ori 与 Thumb 均残留）；但**权威索引 emoji.db 实时更新**——取消的表情立即从索引消失。

**P3 判定 = 通过**，密钥提取（官方 windows_ntqq_get_key.ps1，静态分析 wrapper.node + DEBUG_ONLY_THIS_PROCESS 启动调试版 QQ，用户在新窗口登录瞬间断点命中，脚本自行终止调试进程——"闪退"表象即预期行为，常规 QQ 不受影响）拿到 16 字符 passphrase。

**emoji.db 解密参数（与 nt_msg.db 不同，逐项实测对拍确定）**：
- 结构 = **1024 字节 NTQQ 自定义头**（头部无盐、无明文 SQLite 标记）+ SQLCipher 主体；
- `cipher_page_size = 4096`；`kdf_iter = 4000`；
- `cipher_hmac_algorithm = HMAC_SHA512`（**nt_msg.db 官方脚本注释写 HMAC_SHA1，emoji.db 实测是 SHA512**——两者不同库不同参数，勿照抄）；
- `cipher_kdf_algorithm = PBKDF2_HMAC_SHA512`；
- 盐 = 剥头后前 16 字节（SQLCipher 标准）；
- 纯 C# 实现路径：PBKDF2-SHA512 4000 轮派生 32 字节 AES-256 密钥 + HMAC-SHA512 校验 + AES-CBC 解页（System.Security 全覆盖，零原生依赖），或打包 sqlcipher3 等价物。

**对账验证（本机真实数据）**：`fav_emoji_info_storage_table` 403 行 = 爱心分页真实收藏数；MD5 在列 **`80011`**（表列名是混淆的纯数字，SQL 里必须加双引号引用，否则被解析为整型字面量）；磁盘 442 - 索引 403 = **39 个孤儿全部正确识别**（含探针刚取消的那张）；索引有磁盘无 = 0。对账查询成立，Phase B 全链路打通。
- **明确边界**：图库（Library）中已导入的副本与 QQ 侧删除**永不联动**——导入即出库，独立存在。这是用户资产，QQ 取消收藏不能波及。

### 4.5 多账号绑定模型（一对多，2026-09-30 用户定案，取代此前的"自动跟随"方案）

原则：**软件不主动绑定任何账号**——检测、猜测、询问，绑定永远由用户拍板；一个软件可同时绑定多个 QQ。

**事实基础（2026-09-30 本机实测 + 检索）**：

- 每个账号的数据完全隔离在 `Tencent Files\<uin>\nt_qq\`，personal_emoji 天然按账号隔离；
- 活跃账号存在**持续写入的热文件**（`nt_db\nt_msg.db-wal`，本机当前账号实测今天 05:15 仍在写；兜底信号 `nt_data\mmkv\*`、`nt_data\log\*`），休眠账号的热文件冻结（本机另一账号停在 2024-02）——热文件 mtime 用来**猜**"玩家当前在玩哪个号"；
- **QQ NT 官方支持多账号同时登录**（登录页左下角"添加账号"）；
- 不存在明文的"当前账号"标记（登录相关库全部加密、`%APPDATA%\Tencent\QQNT` 实测为空）。

**A. 启动时：检测 → 猜测 → 询问（一次性，不打扰）**

- 启动后台扫描 `Tencent Files\*\nt_qq`：各账号热文件 mtime（用于猜"当前账号"）+ personal_emoji/Ori 数量统计；
- **无任何绑定时**：若猜到含表情的账号 → 主窗口加载后弹一次 iOS Alert：「检测到 QQ 账号 1234567890（441 个收藏表情，最近活跃：今天 05:15），要绑定它的 QQ 表情吗？」［绑定］［稍后］［不再询问］；
- **已有绑定时**：仅当出现**新的**未绑定账号成为最活跃者，才同样询问一次；
- 拒绝记录：`QqPromptDismissedUins`——"不再询问"后对该账号永不再问；"稍后"仅本会话不重复弹；
- 猜错无后果：用户拒绝即可，设置里的绑定对话框随时兜底（A 是便利，B 是正门）。

**B. 设置里：「绑定 QQ 表情」对话框（主动探测 + 多选 + 辅助判断）**

- 设置页按钮 → 扫描全部账号 → 逐行列出：
  - 账号 uin（已绑定的显示当前别名）、**收藏表情数**（Ori 计数）、**最近活跃时间**（热文件 mtime →「今天 05:15」/「2024-02-19」）、绑定状态；
  - **快速预览**：行内横向缩略图条（Thumb 静态图前 8~12 张；gif 无 Thumb 用 Ori——BitmapImage 原生只解 GIF 第一帧，正合适）；
- 多选勾选 → ［绑定所选］→ 每个绑定各启动 watcher + 建镜像 + 出选项卡；
- 已绑定的行可［解绑］：只摘镜像与选项卡，**Library 已导入的副本不动**（导入即出库原则）。

**C. 运行期**：每个绑定一个独立 FileSystemWatcher + 一份镜像，互不干扰（2~3 个 watcher 成本可忽略）；某绑定目录消失（账号在本机被删/数据迁移）→ 该选项卡空状态「数据目录不存在」+ 引导解绑，其余绑定不受影响。

**明确不做**：多账号合并视图（违背"镜像我在 QQ 里看到的那一页"）；自动跟随切账号（已被绑定模型取代——不再"猜着切"，只"问着绑"）。

**config**：`QqBindings: [{Uin, Alias, BoundAt}]` + `QqPromptDismissedUins`。

### 4.6 导入语义定案：复制转正，镜像不可打标签（2026-09-30）

**导入 = 复制一份进 Library，绝不引用 QQ 原地文件**：

- personal_emoji 是**易失缓存**：QQ 自带"清理存储空间"、按需懒加载、删号/卸载/重装/迁移数据目录都可能动它；图库核心契约是"物理文件为身份"，引用外部文件等于把图库地基架在别人的临时目录上；
- "只想用一次"已由 QQ 页零拷贝发送覆盖；导入动作本身就是用户把这张表情**收编转正**进自己的收藏，理应从此不依赖 QQ 活着；
- 删除对称性：删图库项 = 删自己的副本，永不误删 QQ 的数据；
- 硬链接方案否决：QQ 数据目录可设在别的盘（跨卷不可用）、QQ 改写文件即断链，收益仅省几百 MB。

**标签语义（玩家有对 QQ 导入表情增删标签的需求）**：

- 导入后 = 图库一等公民，增删标签直接走**既有**标签编辑器（右键编辑/批量编辑），零新机制——这是"复制"的决定性优势：引用原地则需为外部文件另造一套标签存储与生命周期；
- **镜像项（QQ 页未导入的）不可打标签**：它是 QQ 数据的视图不是数据；想整理就一键导入再打标；
- 导入时自动加「QQ」来源标签（可自由增删，仅作初始归类与筛选入口）；
- 导入后 `LastUsedTime` 取**源文件 mtime**（≈收藏时间），避免"全部导入"把几十张挤进同一时刻、污染「最近」排序。

## 5. 地基改造（两特性的公共前置，也是现存 bug 的修复）

### 5.1 入库规则升级（AddStickersFromPathAsync 内部改造，签名不变）

1. **MD5 去重**：入库前算源文件 MD5；命中已存在（新规则文件名即 MD5，旧 Guid 文件查 JSON 的 Md5 字段，见 3）→ 跳过 + 状态栏提示「N 张与图库重复」；
2. **魔数定扩展名**：落盘名 `<MD5大写>.<真实扩展名>`；现库 Guid 文件不动（真相源是物理文件+JSON 合并，改名会断 JSON 关联，不做迁移）；
3. **stickers.json 增 `Md5` 字段**（新记录写入；旧记录惰性补算），用于「QQ 页已导入」角标与去重；
4. **webp 处理（2026-09-30 终版定案：转码归一，对齐 QQ 收藏管线哲学）**：取证确认 QQ 的做法不是本机转码工具——安装目录无独立编解码 DLL（Chromium 内嵌 libwebp 只管"能显示"），收藏与聊天缓存实测均为 0 webp 且带 `_720`/`.avif.tmp` 服务端多版本渲染痕迹、商城表情为"私有加密源+`_aio.png` 渲染版"双文件——即腾讯靠**内嵌解码器 + 服务端转码体系**让落地的文件天生就是 jpg/gif/png。我们对齐：入库时 WIC 试解码（装了微软"WebP 图像扩展"即通过，本机已装 `Microsoft.WebpImageExtension`）→ `MaterializeAsync` 转码为 **PNG 落库**（`PreservePixelFormat` 保透明通道，动图取首帧；WPF 内置 PngBitmapEncoder，零外部依赖）；解不动（无解码器）才跳过计数。图库内从此只存 jpg/gif/png/bmp 标准格式；
5. **WebP 环境探测与引导（`WebpSupportProbe`）**：内嵌 68 字节 1×1 WebP 做真实解码探测（比查注册表/包名可靠，WIC 有系统级/用户级多种安装形态），<5ms 进程内缓存。不支持时启动通知串行弹一次警告（QQ 绑定询问之后，共用 Alert 通道防叠加）：说明影响范围（仅拖放导入受限、QQ 收藏同步不受影响），按钮「打开安装页」直达商店 PDP（`ms-windows-store://pdp/?ProductId=9MVDQCNCXSTG`）/「知道了」；config 存 `WebpNoticeDismissed`，处理过永久记住，装好扩展后自然不再弹；
5. 半写防御进入统一入口（QQ 导入用）。
